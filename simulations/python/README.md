# simulations/python

Численные модели и визуализации к теоретической части (`../../theory/`).

## Установка

Окружение фиксируется парой **`pyproject.toml` + `uv.lock`**. Лок содержит точные
версии всех транзитивных зависимостей с хешами и одинаково работает на Windows,
Linux и macOS. Версия самого интерпретатора задана в `.python-version`, поэтому
предустановленный Python на чистой машине **не нужен** — `uv` скачает нужный сам.

### Чистая машина

```bash
git clone <repo> && cd TheoryOfAnything/simulations/python
uv sync --locked       # ставит Python 3.13 + все пакеты ровно по локу
uv run pytest          # проверка, что окружение живое
uv run python Photon.py
```

Если `uv` ещё не установлен — запустите `bootstrap.ps1` (Windows) или
`bootstrap.sh` (Linux/macOS): они поставят `uv` и выполнят синхронизацию.
Установить вручную:

```powershell
winget install astral-sh.uv                              # Windows
irm https://astral.sh/uv/install.ps1 | iex                # Windows, без winget
curl -LsSf https://astral.sh/uv/install.sh | sh           # Linux / macOS
```

Если проект лежит **не на том диске**, где установлен uv (обычная ситуация на
Windows: uv в `C:`, репозиторий в `M:`), вместо `uv sync` используйте
`venv-init.cmd` — см. следующий раздел.

### Проект на другом диске, чем uv

По умолчанию uv не копирует пакеты в `.venv`, а **жёстко линкует** их из
глобального кеша (на Windows это `%LOCALAPPDATA%\uv\cache`, то есть диск `C:`).
Жёсткая ссылка не может пересекать границу тома, поэтому если проект лежит на
другом диске — например на `M:` — `uv sync` спотыкается и печатает:

```
warning: Failed to hardlink files; falling back to full copy.
         This may lead to degraded performance.
         If the cache and target directories are on different filesystems,
         hardlinking may not be supported.
```

Установка при этом всё равно проходит, просто медленнее и с полным копированием.

Для этого случая рядом лежит **`venv-init.cmd`** — он делает ровно одно:
восстанавливает окружение по локу, обойдя проблему с томами.

```bat
set UV_LINK_MODE=symlink
uv sync --locked
```

Зависимости он **не пересчитывает** — это отдельная задача, см. «Изменение
зависимостей» ниже. Полная версия файла ещё умеет откатываться на `copy`, если
symlink упрётся в права, и переключает кодовую страницу консоли на UTF-8.

`UV_LINK_MODE` (то же самое, что ключ `--link-mode`) задаёт способ раскладки
пакетов из кеша в `.venv`. Доступные значения и их цена:

| Режим | Плюсы | Минусы |
|---|---|---|
| `hardlink` — по умолчанию | быстро, место не дублируется | **не работает между томами** |
| `symlink` | быстро, место не дублируется | на Windows нужны права: без Developer Mode или запуска от администратора падает с `A required privilege is not held by the client (os error 1314)`. `.venv` перестаёт быть самодостаточным: `uv cache clean` превращает ссылки в битые |
| `copy` | самый надёжный: `.venv` ни от чего не зависит | занимает место, ставится дольше |
| `clone` | CoW-копия: быстро и самодостаточно | нужна ФС с reflink (APFS, Btrfs, XFS); на NTFS недоступно |

**Более чистая альтернатива** — не менять способ линковки, а перенести сам кеш
на тот диск, где лежит проект. Тогда `hardlink` снова работает, установка
остаётся быстрой, а `.venv` — самодостаточным:

```bat
setx UV_CACHE_DIR "M:\.uv-cache"
```

`setx` прописывает переменную для будущих сессий; в текущем окне нужен `set`.
После смены кеша первая синхронизация скачает пакеты заново.

Переменную можно не выносить в окружение, а прописать в `pyproject.toml`
(`[tool.uv] link-mode = "copy"`) — но для этого проекта так делать не стоит:
расположение на разных дисках это свойство конкретной машины, а не проекта, и
такая настройка навязала бы медленный режим ещё и CI, и всем остальным.

> **Важно:** переменная, выставленная внутри `venv-init.cmd`, живёт только до
> конца этого окна. Следующий `uv add` или `uv run` из обычной консоли снова
> упрётся в жёсткие ссылки. Если проект постоянно живёт на другом диске —
> задайте `UV_CACHE_DIR` (или `UV_LINK_MODE`) через `setx` один раз, а
> `venv-init.cmd` держите для разовой инициализации с нуля.

### Ключ `--locked`

`uv sync --locked` **падает**, если `uv.lock` разошёлся с `pyproject.toml`,
вместо того чтобы молча пересчитать зависимости. Это и есть разница между
воспроизводимой сборкой и «почти воспроизводимой» — используйте этот ключ
везде, где важно получить ровно то, что было закоммичено. Без ключа
`uv sync` при расхождении обновит лок сам.

### Изменение зависимостей

```bash
uv add scipy               # добавить: правит pyproject.toml, uv.lock и .venv
uv remove sympy            # убрать
uv lock --upgrade          # поднять версии в пределах ограничений
```

`uv.lock` **коммитится** — без него воспроизводимости нет.

Отдельная команда `uv lock` руками нужна редко. Обычные `uv sync` и `uv run`
сами пересчитывают лок, если `pyproject.toml` изменился, — `uv lock` полезен
только когда нужно обновить лок, ничего не устанавливая, или при `--upgrade`.

Как ведут себя команды, когда лок разошёлся с `pyproject.toml`:

| Команда | Поведение |
|---|---|
| `uv sync` | молча пересчитывает лок и приводит `.venv` в соответствие |
| `uv run …` | то же самое, перед запуском скрипта |
| `uv sync --locked` | отказывается: `The lockfile at uv.lock needs to be updated, but --locked was provided` |
| `uv sync --frozen` | берёт лок как есть, расхождение не проверяет |

### Без uv

`requirements.txt` — запасной путь, генерируется из лока и вручную не правится:

```bash
uv export --frozen --no-dev --format requirements-txt > requirements.txt
```

Тогда на другой машине: `python -m venv .venv && pip install -r requirements.txt`.
Учтите, что так не фиксируется версия самого Python.

### Что проверяет CI

`.github/workflows/simulations.yml` на каждый push делает ровно то, что сделает
человек на чистой машине: `checkout` → `uv sync --locked` → `uv run pytest`,
параллельно на `ubuntu-latest` и `windows-latest`. Пока workflow зелёный,
инструкция выше гарантированно работает.

## `LeptonSpectrum.py`: результат

Модуль проверяет спектр масс из `../../theory/04-3` и `04-5` по полной сетке
частиц поляризации вакуума (12 частиц от электрона до t-кварка), нормируя
лестницу **на самую тяжёлую** частицу. Итог: **схема в нынешнем виде
предсказательной силой не обладает.**

| Что установлено | Значение |
|---|---|
| Поведение интеграла перекрытия | `Gamma_n ~ tau_n^(-1.000)` — закон масс не кубический, а квадратичный: `m ~ n^2` |
| Дно лестницы | 17.99 МэВ; электрон, u- и d-кварк под него не попадают |
| Контрольный тест на случайной лестнице | медиана 6.87 % (модель) против 5.73 % (случайная); лишь 32.5 % розыгрышей хуже |
| Влияние `eta_eff` на отношения масс | 0.13 % при изменении eta в 2.7 раза — параметр каустики задаёт только общий масштаб |
| Подбор тройки уровней | удаётся при **любом** показателе p от 1.5 до 4.0 с точностью < 1 % |

Отдельный результат — **теорема** (`koide_no_solution_proof()`): на степенной
лестнице `m ~ n^p` с чётным p соотношение Коиде не выполняется точно ни для
какой тройки уровней. Условие сводится к диофантову уравнению
`i^2+j^2+k^2 = 4(ij+jk+ik)`, не имеющему решений (спуск Ферма по модулю 4).
Это вскрывает противоречие между `theory/04-4` и `theory/04-5`.

Разбор: `../../theory/04-5-spektr-na-setke-polyarizacii.md`,
`../../theory/04-6-koide-i-otbor-urovney.md`.

## `CubicQuintic.py`: результат

Расчёты к подглаве `theory/02-5-nasyshchayushchiy-chlen.md` (пункт T-34).

```
1. точное одномерное решение
   f^2(s) = 4 lam / [ g + sqrt(g^2 - 16 h lam/3) * cosh(2 sqrt(lam) s) ]
   макс. невязка 1e-6 на трёх наборах (lam, g, h)
   условие локализации:  D > 0  <=>  lam < 3 g^2 / (16 h)

2. окно частот Q-шара в D = 3 (условие Коулмена)
   omega_min^2 = m^2 - 3 g^2 / (16 h),   f_*^2 = 3 g / (4 h)
   тождество:  lam < 3g^2/(16h)  <=>  omega^2 > omega_min^2
   => окно непусто при ЛЮБЫХ g, h > 0: существование установлено для класса

3. теорема подобия: Lam = lam * h / g^2 — единственный параметр
     lam      g      h      Lam   f0*sqrt(h/g)   E*sqrt(h)   R*g/sqrt(h)
   0.100   1.00   1.00   0.1000     0.91885213    15.19485        37.556
   0.400   2.00   1.00   0.1000     0.91885213    15.19485        37.641
   0.050   1.00   2.00   0.1000     0.91885213    15.19484        37.547
   0.900   3.00   1.00   0.1000     0.91885213    15.19486        37.573
   0.025   0.50   1.00   0.1000     0.91885213    15.19483        37.644
   совпадение до седьмого знака при разбросе lam в 36 раз, g в 6, h в 2

4. основное состояние (приведённые единицы, g = h = 1)
     Lam        f0        E       R
   0.020   0.568848    3.029    79.7
   0.050   0.800189    6.029    50.9
   0.080   0.895218   10.356    40.9
   0.100   0.918852   15.195    37.6
   окно 0 < Lam < 3/16 = 0.1875; тонкая стенка при f_*/A = sqrt(3)/2 = 0.866025

5. контроль отвергнутого профиля
   Ф = (2/sqrt(g)) / sqrt(rho/rho0 + rho0/rho + 2) при h = g^2/3
   требуемая lam меняется от -16.34 до +0.85 => решением не является
   связь h = g^2/3 несогласована по размерности: [h] = [g]^2/[lam]
```

Следствие для правила отбора уровней (T-15): любое безразмерное отношение —
функция одного числа `Lam`. Если уровни спектра масс суть радиальные моды одного
солитона, то `E_1/E_0 = 206.77` и `E_2/E_0 = 3477.2` обязаны получиться при одном
и том же `Lam`. Тест сформулирован, но не проведён: возбуждённые ветви лежат в
экспоненциально узкой окрестности тонкостенной амплитуды и равномерной
пристрелкой не разрешаются.

Запуск:

```bash
python CubicQuintic.py
```

## `Proton_new.py`: результат

Расчёты к подглавам `theory/05-10-faza-protiv-polozheniya.md` и
`theory/05-11-deficit-obhoda.md` (пункт T-33). Отличия от `Proton.py`:
одна нить вместо трёх, фаза возбуждения psi разведена с геометрическим углом
phi, отдача дифференциальная, дробный заряд показан счётчиком доли обхода,
а цветовая фаза фокусов гонится теми же долями, что и заряд.

Три атрибута маркера фокуса кодируют три независимые переменные: заливка —
цветовую фазу, обод — опознавательный цвет моды, размер и яркость — фазу
возбуждения psi. В координаты psi не входит вовсе.

```
1. вырождение постоянного сдвига фазы
   max |C(th; phi+pi) - C(th+2pi; phi)| = 3.468e-15
   => двух u-нитей не существует: это одна кривая

2. отдача: синфазная против дифференциальной
      eps      синфазная     дифференциальная
     0.00      3.468e-15               0.0000
     0.10      3.684e-15               0.1997
     0.30      3.749e-15               0.5910
   синфазная (как в Proton.py) не снимает вырождения ни при какой амплитуде

3. треугольник фокусов в покое, R = sqrt(3) r
   стороны 4.393 / 3.619 / 3.041 r  =  1.0503 / 0.8653 / 0.7272 фм
   max/min = 1.444, разброс 36.7 %
   среднее ребро 3.684 r = 0.8809 фм  (= L из 5.9)
   расстояния фокусов ОТ ОСИ: 2.732 / 2.232 / 1.232 r = 0.653 / 0.534 / 0.295 фм
   отношение max/min = 2.217; все три внутри r_p = 0.8409 фм
```

| Проба | z | Предсказание | Предел | |
|---|---|---|---|---|
| Атомные часы | 0 | −2.4e−14 /год | 1.1e−18 /год | ×21 976 |

но тогда и предсказания бега α нет.
